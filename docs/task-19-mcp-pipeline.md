# День 19. Композиция MCP-инструментов: цепочку собирает модель — устройство

День 18 дал агенту третий MCP-сервер (курсы валют). День 19 проверяет другое: сервер объявляет
**три независимых инструмента** — получить курсы, свести их, сохранить в файл, — а нужную
последовательность из них собирает **модель** по обычной просьбе, без зашитого порядка и без
кода, который знал бы про три шага сразу.

## 1. Что просит задание и чем подтверждается

| Требование | Где сделано | Чем подтверждается |
| --- | --- | --- |
| Три отдельных MCP-инструмента: курсы, сводка, файл | `mcp-pipeline/.../mcp/GetExchangeRatesTool.kt`, `SummarizeRatesTool.kt`, `SaveToFileTool.kt` | `:mcp-pipeline:test` (20 проверок), `./gradlew :mcp-pipeline:mcpTools` |
| Инструменты независимы: каждый вызывается сам по себе | объявления в `PipelineMcpServer.tools()` | `ExchangeRatesToolTest`, `SummarizeRatesToolTest`, `SaveToFileToolTest` |
| Цепочку собирает модель по описаниям, порядка в коде нет | описания инструментов (`«ответ — JSON целиком: его принимает summarizeRates»`) | живая демонстрация `:server:pipelineDemo` (§6) |
| Данные передаются между шагами | аргументы `rates` и `content` | `PipelineProtocolTest` (сверка файла со сводкой), `PipelineDemoTest` |
| Курсы берутся из накопленной истории службы | `CurrencyRateRepository.latest()` | `PipelineProtocolTest` (временная база), `GetExchangeRatesTool` |
| Сохранение в файл | `SaveToFileTool.writeReport` | `SaveToFileToolTest` (6 проверок) |
| Отказы — `isError` с причиной, сервер продолжает работать | `PipelineInputException` в каждом инструменте | проверки отказов в трёх наборах |

## 2. Почему это отдельный модуль `:mcp-pipeline`

У пайплайна свой предмет (отчёты по курсам), своя настройка (`PIPELINE_OUTPUT_DIR`) и своя точка
входа; к службе курсов он обращается только на чтение — через `SqliteCurrencyRateRepository` из
`:currency-monitor`. Внутрь `:currency-monitor` его не положили: тот модуль собирает данные и живёт
на ВМ службой, а этот пишет файлы на машине человека, и один fat JAR на две разные работы означал
бы, что ради отчёта тащат минутный сборщик. Внутрь `:mcp` — тоже нет: там общая часть (объявление
инструмента, сборка сервера, режимы stdio), и вторым предметом её бы разбавили. Общая часть при
этом не скопирована: `:mcp-pipeline` пользуется ею так же, как `:mcp-github` и `:currency-monitor`.

Флага `--mcp` у точки входа нет (в отличие от службы курсов): работы без клиента у пайплайна не
существует, поэтому запуск без аргументов и есть сервер. База открывается лениво, внутри сборки
сервера: в режиме `--list-tools` список берётся из объявлений, и требовать ради справки настроенную
историю курсов было бы нельзя.

## 3. Что каждый шаг принимает и отдаёт

**`getExchangeRates(base?, currencies?)`.** Читает последние курсы и отдаёт JSON: `base`,
`updatedAt` (момент самого свежего значения, а не время ответа), `rates` — курсы к базе,
`missing` — валюты, о которых спросили, а истории у них нет. База — аргумент, а не всегда рубль:
история хранится к рублю, но вопрос «сколько долларов стоит евро» законен, и пересчёт делается
там, где есть оба курса. Курс базы к самой себе — ровно единица, а не `1.000000`: деление на себя
показало бы округление, которого не было. Пересчёт к другой базе округляется до шести знаков
(`HALF_UP`) — точность, которую не жалко потерять, и предел, за которым модель начала бы считать
по тексту. Валюта без истории в курсы не попадает и ноль вместо себя не подставляет: ноль — это
утверждение о курсе, которого в данных нет.

**`summarizeRates(rates)`.** Принимает документ первого шага **целиком** и отдаёт текст:
`Сводка курсов к RUB на 2026-09-28 10:37 UTC`, число валют, размах между крайними и по строке на
валюту, где крайние помечены словами («дороже всех»). Порядок валют — тот, в каком они пришли
в документе: сводка описывает переданный ответ, а не историю, и переставлять строки значило бы
показывать не то, что передали. Числа печатаются как пришли, с запятой в дробной части (сводку
читает человек), а размах — величина посчитанная, поэтому хвостовые нули у него убраны.
Строка принимается наравне с числом: документ составляет наш инструмент, но его может составить
и модель, а `"84.3414"` и `84.3414` для сводки — одно и то же значение.

**`saveToFile(name?, content)`.** Пишет текст в каталог отчётов и отвечает путём, размером и
SHA-256. Имя приходит от модели, поэтому проверяется: разделители каталогов, абсолютный путь,
переход вверх и пустая строка — отказ, а не молчаливое укорочение до имени файла. Каталог
создаётся записью, а не запуском сервера, файл перезаписывается (отчёт за ту же минуту — тот же
отчёт), имя по умолчанию — `rates-ГГГГ-ММ-ДД-ЧЧММ.md` по часам сервера.

## 4. Почему порядок не зашит

Задание дня — композиция, а не «одна кнопка, которая делает всё». Один инструмент «сделай отчёт»
проверял бы ровно ничего: передача данных между инструментами существует там, где их вызывают
по отдельности, и именно её видно в проверках (`rates` второго шага — это ответ первого,
`content` третьего — ответ второго). Поэтому сервер отдаёт агенту три объявления, а порядок
выбирает модель; в описаниях сказано, чей ответ принимает следующий шаг, — этого достаточно,
чтобы цепочка собралась, и мало, чтобы собраться без модели.

## 5. Отказы

Каждый инструмент отвечает результатом с `isError` и причиной словами — не исключением:
недопустимая база, незнакомая валюта, пустая история, база без курса, не разобранный документ,
нечисловой курс, имя файла с каталогом. Причина уходит модели, и она может исправить вызов или
позвать первый шаг заново; исключение же отменило бы ответ человеку целиком, хотя вопрос был
не только об инструменте.

## 6. Живой прогон

`./gradlew :server:pipelineDemo -Pdemo.live=1` — модель `deepseek-v4-flash`, сервер инструментов
поднят настоящим процессом по протоколу MCP, база курсов временная (три курса: EUR 95,8709,
USD 84,3414, GEL 32,1693). Просьба — «получи текущие курсы USD, EUR и GEL относительно рубля,
сформируй краткую сводку и сохрани её в файл»; ни имён инструментов, ни порядка в ней нет.

Прогон 2026-09-28: модель позвала `getExchangeRates` → `summarizeRates` → `saveToFile` (три
раунда, 3247 токенов), в сводку ушёл документ первого шага (155 знаков), в файл — сводка второго
(149 знаков), в файле на диске те же 149 знаков (`rates-2026-09-28-1048.md`), ответ человеку —
«Готово. Курсы получены, сводка сформирована и сохранена.». Проверки сверяют и порядок вызовов,
и данные на каждом переходе, и содержимое файла.

Сравнение шага 1 и шага 2 — по данным внутри документа, а не по строкам целиком: текст передаёт
модель, и различие в пробелах по краям не значит потери данных. Последний переход (аргумент →
файл) сверяется точно: он идёт внутри инструмента, где вольностей нет.

## 7. Как запускать

```
./gradlew :mcp-pipeline:test                 # 20 проверок трёх инструментов и цепочки
./gradlew :mcp-pipeline:mcpTools             # список инструментов без клиента и без базы
./gradlew :server:pipelineDemo -Pdemo.live=1 # живая демонстрация: цепочку собирает модель
```

Отдельным процессом сервер пайплайна запускается из fat JAR (так его и поднимает приложение,
когда история курсов не рядом): `./gradlew :mcp-pipeline:fatJar`, затем
`PIPELINE_OUTPUT_DIR=… CURRENCY_DB=… java -jar mcp-pipeline/build/libs/mcp-pipeline-1.0.0-all.jar`.
То же — командой в окружении приложения: `PIPELINE_MCP_COMMAND="ssh vps java -jar /opt/mcp-pipeline/mcp-pipeline.jar"`.
